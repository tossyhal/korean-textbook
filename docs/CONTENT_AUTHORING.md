# 教材制作・週ごとの受け入れ

現在の改訂は[REFINEMENT.md](REFINEMENT.md)、評価基準は[ASSESSMENT.md](ASSESSMENT.md)を参照する。元の仕様書は履歴であり、現在の改訂とユーザー指定を優先する。教材は各課個別ファイル、週ごとにexportする。

## 前週で見つかった失敗を繰り返さない

- 本文は学習者が外部教材なしで理解できる説明。意味・作り方・場面・日本語との差・典型誤りを、具体例と対照で教える。
- 初出語は意味/品詞/辞書形/初出を登録。前週の同語はIDと定義を再利用する。活用形を新語として数えない。
- grammarには初出課内のsectionIdを指定し、誤答から正しい本文へ戻す。
- 文法を追加する場合や参照先の段落を変更する場合は`src/content/grammar-reference-data`の明示的な対応も確認する。現在の165項目は問題ID（`questionId`）または段落番号（`paragraphIndices`）を指定し、必要に応じて例文（`example`）を対応付ける。IDを安定させ、参照先と内容を検証する。`getGrammarReference`は対応が欠落・不正な場合に任意の問題や段落へフォールバックしない。
- 例文・会話・練習の原文を出口・週試験にそのまま流用しない。学習済み表現の別状況や短い情報統合を使う。単語差替えだけの量産を避ける。
- 日本語の意味回答は選択式を基本にする。listening+optionsは対応済み。自由入力なら求める単位を限定し同義形を許容する。
- 韓国語自由文を単一文字列に固定しない。固定組立なら使用語/主語/助詞を指定し、句点や未縮約形の許容を検討する。
- normalization:standardは空白を削除せず連続空白を1個にし、文末句読点を除く。分かち書きでは空白なしを許容しない。exactは意図がある場合のみ。
- `normalization: 'latin'`は明示的に指定した英数字の問題に限り、全角英数字と英大文字を正規化する。ハングル全体にNFKCを適用しない。
- 想起・productionは各課固有。productionは実際に使える複数文のモデルと観点を用意。
- 試験は読む/聞く/入力/書く/話すを分ける。自動と自己評価を混同しない。
- 聴解はaudio.textに原文、promptは答えを漏らさずoptionsで理解を問う。TTSはunverified。微妙な音対立はrequiresVerifiedAudioまたは自己確認にする。
- 出典は実際に開いた資料と確認した事項のみ。トップページ閲覧で特定用法を照合済みにしない。全文の自然さの保証とは区別する。

## 検証

1. 現在までの全課をvalidateContent(...,false)で検証。
2. 型、教材の採点回帰テスト、文法参照の対応と例文の検証、担当lint/format。
3. 新規Solセッションで教材と一次資料を独立レビュー。
4. 指摘修正後、親が検証して週単位でコミット。
5. CONTENT_STATUSへ本文/演習/評価/言語照合/音声/動作の状態を記録。
