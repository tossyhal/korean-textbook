# ロールプレイの教材契約

`Lesson.roleplay`は省略可能。`production.model`とは別で、各ターンに条件に応じた回答例を2件以上置く。例は型の構造を示すもので、教材としての言語照合・音声確認はしていない。

```ts
roleplay: {
  scenario: "店で注文する",
  turns: [{
    partner: { korean: "何を注文しますか", japanese: "相手の発話の訳" },
    goal: "希望する品と数量を伝える",
    responseExamples: [
      { korean: "回答例1", japanese: "回答例1の訳", note: "条件1の場合" },
      { korean: "回答例2", japanese: "回答例2の訳", note: "条件2の場合" },
    ],
    rubric: ["希望する品と数量を伝えたか"],
  }],
}
```

`partner`と各回答例は既存の`Example`型で、必要に応じて`audio`の出典・ライセンス・声・確認状態を記録する。文言は実教材に置き換え、条件の異なる例と自己確認項目を各ターンに用意する。相手の原文と訳、回答例は最初は閉じている。利用者が相手の音声を再生し、返答を考えて録音し、必要に応じて例と観点を確認し、ボタンで次に進む。録音や再生に失敗しても進行を妨げず、未実施を完了や得点として扱わない。AIによる会話・発音評価はない。

進捗には課IDごとの現在のターン番号と各ターンの下書きのみを保存する。JSONの取り込み時に教材に存在する課とターン数を検証する。録音データは画面のメモリだけに置き、バックアップには含めない。ターン移動・画面離脱で再生と録音を停止する。ロールプレイの操作で課の完了は記録しない。

共通の音声ボタンは再生できない場合にエラーを表示する。音声の確認状態は教材のメタデータに保持し、合成音声の未確認状態を再生のたびに表示しない。実機・実音声の確認、言語的照合、ブラウザーモックの動作確認は別々に記録する。再生成功だけで音声の内容を確認済みにしない。
