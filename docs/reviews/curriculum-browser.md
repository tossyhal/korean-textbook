# 収録課ブラウザー回帰テストのレビュー

2026-11-12。新規Solレビュー。対象は`tests/browser/curriculum.spec.ts`、`playwright.production.config.ts`、package/miseの実行入口、`docs/VERIFICATION-curriculum.md`、`QuestionView.check`の時刻取得変更に限定する。現状は次のP2指摘があり、回帰検証全体の受入は保留する。アプリコードとテストは変更していない。

## 指摘

### P2：全課への非音声固定解の強制を、活動に応じた操作へ変える

`tests/browser/curriculum.spec.ts:59-62`は、演習・出口テストに非self・非listening問題が必ずあると要求する。仕様のDay43〜49は音声中心、Day51・54は作文・自由発話中心であり、仕様とスキーマはこれらの活動を固定解に置換することを要求していない。正当な聴解・自己評価中心課を追加すると、本文や学習操作が正常でも、この検索だけで全課回帰が失敗する。非listeningでも`requiresVerifiedAudio`の未確認問題は選択対象になり得るため、「音声不要」の判定としても不足している。さらに同ファイル90-94行は未確認音声を要求するself問題にも「答え合わせ」を探すが、その問題のボタンは「自己評価を記録」である。

固定解を必須とする代わりに、課の活動に適した意味のある操作を必須にする。利用可能な固定解がある課では現行の採点・保存・再読込照合を維持する。自由回答中心課では回答入力、自己評価の記録、`result: self`と履歴・下書きの復元を確認する。未確認音声中心課では未実施表示、採点不可、操作後も採点履歴が増えないことと、回答下書き等の保存を確認する。音声再生モックで操作を検証しても実音声確認済みとは扱わない。活動が見つからなければ明示的に失敗させ、無条件skipや本文表示だけへの後退は避ける。

### P2：本番テストは既存サーバーを再利用しない

`playwright.production.config.ts:10`の`reuseExistingServer: true`により、4173番で同じパスに応答するサーバーが既にあれば、直前のbuild成果物を配信するpreviewを起動しない。例えば4173番の開発サーバーを再利用すると、`test:preview`の成功を本番ビルドの実動成功として報告できてしまう。古い別成果物を配信するサーバーでも同じ問題が起きる。

本番検証用設定では`reuseExistingServer: false`として、既存プロセスがある場合は明確に失敗させる。`--strictPort`だけではPlaywrightがサーバー起動自体を省略するケースを防げない。

## 限定的に受け入れられる点

- `lessons`から収録課ごとのテストを生成し、35/56課・未収録21課を記録する構成は、未収録課を検証成功に含めていない。56課の完成は別検査と明記している。
- 各収録課の本文先頭段落、例文・会話、演習・出口問題、出典URL、前提・次課リンクを照合する。固定解への実入力、採点結果、メモ・作文・ロールプレイ下書きの再読込、時刻を含む履歴配列の不変性を検証する。本文全段落の内容や言語品質を照合するテストではない。
- 各課テストはページ例外とconsole.errorを収集する。390pxと主要画面移動テストには同じ監視がないため、文書のエラー検出記述は各課テストの範囲として読む。390px検査は最初・最後の課のみで、実機確認とは区別されている。
- roleplayの自動評価なし表示、voiceTransferの音声未確認表示、未確認の重要音声問題の採点無効、selfの自動採点なし表示を明示的に確認する。実音声・発音・マイク・IME・iPhone/Windows実機を未確認とする記録は適切である。
- `test:preview`はbuild後に本番設定を呼び、設定のbaseURLとViteのbaseは`/korean-textbook/`で一致する。mise入口も同じスクリプトへ到達する。上記サーバー再利用問題を除けば本番basepathでの確認経路がある。
- `QuestionView.check`で`new Date().toISOString()`をイベント処理中に一度取得してupdaterへ渡す変更は妥当である。StrictModeがupdaterを再評価しても同じ回答操作の時刻が一致し、保存された履歴と状態の履歴の不一致を防ぐ限定修正になっている。`update`内の保存など他の副作用全般を解消した変更とは扱わない。

## 実施範囲

仕様、AGENTS.md、README、上記対象と関連スキーマ・描画・保存処理を静的に照合した。本レビューではテスト、build、lint、format、ブラウザー操作を実行していない。39件成功という数値は既存の検証記録に記された結果であり、本レビューによる再実行結果ではない。後半課は未収録なので、その教材の動作や言語品質を確認済みとは扱わない。
