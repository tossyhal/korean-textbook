# App・音声UIの独立受入レビュー

基準コミット：`5a062c9`。対象は共有作業ツリーの`src/App.tsx`、音声コンポーネント、関連ブラウザーテスト。2026-11-12時点のレビューであり、後続の修正を受け入れた記録ではない。実装ファイルは変更していない。

## 確定した指摘

### P2：単体字母の選択肢に表示される音声ボタンが無音になる

対象：`src/App.tsx:475–479`、`src/features/audio/engine.ts:79–81`。

新設された選択肢の音声ボタンは`audio.play(o)`に字母を直接渡す。一方、エンジンは`isJamoOnly(text)`なら`false`で終了する。`SpeakableText`が持つ字母名・音節への変換を通らず、戻り値`false`も無視するため、音声もエラー表示もない。`catch(() => {})`によりPromiseの失敗も利用者には伝わらない。

agent-browserの専用セッションで、韓国語音声と`SpeechSynthesisUtterance`をモックし、`speechSynthesis.speak`の呼び出しを記録した。次の経路で再現した。

1. `#/lesson/day-01?exercises`の`day-01-ex-08`「唇を丸める母音を選ぶ」を開く。
2. 「ㅜの音声を再生」を押す。呼び出し記録は空のまま、エラー表示もない。回答選択・回答履歴は変わらない。
3. 対照として本文の「ㅜの音節・単語例우を聞く」を押すと、`speak("우")`が呼ばれる。
4. 練習に戻り同じ選択肢の音声を押しても、記録は`["우"]`のまま増えない。

同節`day-01-ex-09`の`ㅁ`・`ㅂ`なども同じ拒否条件に当たる。選択肢でも共通の字母変換を通し、再生失敗時の表示を備える必要がある。追加済みテストは音節`우`を対象にしており、単体字母の失敗を検出できていない。

この範囲で、ほかの確定P1・P2は見つからなかった。

## 確認した動作

対象を限定して、次の11件を1ワーカーで実行し、すべて成功した（8.6秒）。

```sh
mise exec -- pnpm run test:browser tests/browser/media.spec.ts tests/browser/learning.spec.ts tests/browser/finish.spec.ts tests/browser/manual-review.spec.ts tests/browser/wordbook.spec.ts --workers=1 --grep '聴解の停止|別の文字の再生|選択肢の音声|聴解の原文|復習に登録した語彙|回答欄と選択肢|利用できない活動|旧形式の進捗|文法に同じ節'
```

- 聴解を停止・連続再生・画面移動した後の古いコールバックが、再生エラーを出さない。一度完了した聴解は、その後の中断や失敗で回答資格を失わない。現在の再生自体の失敗は表示される。
- 第1節の二つの入力欄は各設問を含む異なるアクセシブルネームを持ち、選択肢グループ名にも設問が含まれる。
- 音節`우`の選択肢音声は、ラジオの選択、drafts、attempts、答え閲覧履歴を変更しない。公開後の答えは発音できる。
- 聴解原文は答えの公開前には表示されず、公開後に折りたたみを開くと発音できる。問題音声の再生ボタン自体は原文をラベルに含めていない。
- 復習に登録した語彙は音声を呼び出す。文法一覧は検索で対象を絞り、対応例文と日本語訳を表示し、音声を呼び出す。
- 第43・44節は未確認の必須音声問題を未実施のまま保ち、利用可能な確認テストと実践が済んでいれば完了できる。未確認問題のattemptを捏造せず、初回正答数も増やさない。第47節は別音声練習を任意と表示し、実施記録なしで完了できる。完了後もattemptsとvoiceTransferRunsが変わらない。
- 旧形式の進捗を復元しても、手動登録した復習項目、1日20件の上限、次回の間隔が維持される。

コード上でも、文法の復習カードは`getGrammarReference`のpromptを問題面、answer・explanation・exampleを答え公開後に使用している。これらの解答表示は公開条件の内側にあり、正解文が先に表示される構造ではない。今回の変更で文法検索や語彙ページングの処理は置き換わっていない。

## 確認の限界

- 上記は制御した合成音声モックの呼び出しとUI状態の検証であり、端末TTSの実聴、音質、母語話者による照合、iPhone・Windows実機確認ではない。
- 追加テストの「別の文字の再生」は本文へのタブ移動を含む。同じ画面に残した聴解を別の文字で中断するケースを直接証明していない。
- Promiseそのもののreject、`unhandledrejection`の監視、解説にしか現れない韓国語の発音、文法復習カードの公開前後を操作したケースは、今回実行したテストに含まれない。コード上のcatchや公開条件の確認を、これらの動作テスト成功として数えない。
- 文法参照データ全165項目の意味的な対応関係・言語品質、新しい回答正規化の内容受入は別レビューの範囲。ここではAppが参照APIの値を表示する接続だけを確認した。
- 全ブラウザーテスト、ビルド、lint、型検査はこのレビューでは再実行していない。共有作業ツリーで別担当の修正が進行しているため、最終統合状態の検証は親担当が行う。
