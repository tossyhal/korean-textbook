# 選択肢音声の修正受入レビュー

2026-11-12。`fix/independent-review-findings`の共有作業ツリーを対象にした独立・限定受入。前回の[App・音声UI受入レビュー](external-app-acceptance.md)で残ったP2「単体字母の選択肢音声が無音になる」の修正と、その周辺の失敗・中断処理を確認した。実装ファイルは変更していない。

## 判定

対象P2は解消した。この範囲で追加の確定P1・P2は見つからなかった。

`src/App.tsx`の選択肢音声は`audio.play(o)`の直接呼び出しではなく、共通の`SpeakableText`を`iconOnly`で利用する。音声ボタンはラジオの`label`の外にあり、字母変換と失敗表示も共通経路を通る。

`SpeakableText`は完全一致する角括弧付き単体字母を取り出して字母名に変換する。確認した実際のTTS呼び出しは`ㅜ → 우`、`[ㄷ] → 디귿`、通常の`우 → 우`。`[ㄷ]`のアクセシブルネームは「[ㄷ]の名前디귿を聞く」であり、終声の実音を再生するという説明にはしていない。音響的な終声の聞き分けを検証したものではない。

## 独立に実行した検証

次の既存・追加テスト8件を1ワーカーで実行し、すべて成功した（5.2秒）。ボタンの存在だけでなく、合成音声モックへ渡る`utterance.text`を確認するケースを含む。

```sh
mise exec -- pnpm run test:browser tests/browser/media.spec.ts --workers=1 --grep '字母の選択肢|角括弧付き字母|選択肢の音声|同じ画面の別の再生|聴解の停止|聴解の原文|音声の生成に失敗'
```

- 単体字母`ㅜ`と角括弧付き`[ㄷ]`から、それぞれ`우`・`디귿`が読み上げ要求される。音声操作ではラジオが選ばれず、通常のラジオ操作は引き続き可能。単体字母ケースではdrafts、attempts、答え閲覧履歴の不変と`label button`が存在しないことも確認した。
- 通常の音節`우`は変換されずに読み上げられ、音声操作だけでは回答や履歴が変わらない。答え公開後、解説側に現れる`ㅇ`を押すと`이응`が要求される。解説音声の前後でもdrafts・attemptsが変わらない。
- `SpeechSynthesisUtterance`の初回生成を例外で失敗させると、選択肢近傍に失敗案内を表示する。再試行では`우`が要求され、案内は消える。ラジオ未選択を維持し、`pageerror`と`unhandledrejection`は記録されなかった。本文側の生成失敗・再試行も成功した。
- 聴解の停止、連続再生、タブ移動後に古い`onerror`を通知しても誤った失敗表示を出さない。完了前の停止は回答資格を与えず、一度完了した聴解は後の中断や実際の失敗で回答資格を失わない。現在の要求自体の失敗は表示する。
- 聴解を一度完了し、再生中に同じ練習画面の`아니에요`を再生して中断した後、古い聴解の`onerror`を通知しても失敗表示が出ず、答え合わせを実行可能なまま保つ。
- 聴解の原文は答え公開前に表示されない。公開後に原文を開いて押すと`의사예요`が要求される。

コード上でも、`SpeakableText`はPromiseのrejectを捕捉し、現行要求なら再生中状態を解除して失敗を表示する。生成例外はPromise executor内からrejectとして伝わるため、この経路で未解決のまま待ち続ける構造ではない。停止はエンジンが保留中のPromiseを`false`で解決し、共通停止通知が要求番号を進めるため、後着の完了・失敗は現行UIへ反映しない。上記の再試行・中断テストと整合している。

## 範囲と限界

- 制御したChromiumの合成音声モックによるUI・呼び出し検証。実端末TTSの実聴、音質、母語話者照合、録音品質、iPhone・Windows実機確認ではない。
- constructor例外を用いたreject経路と再試行は実行した。任意の別種のPromise rejectを直接注入した検証や、内部Promiseの参照を取得して状態を直接検査したものではない。
- 同画面中断テストは完了済み聴解の回答資格保持を確認する。未完了聴解の同画面中断を独立ケースとして追加実行したものではない。
- 実装担当からmedia・learning計36件、型検査、lint成功の報告があるが、本レビューの独立実行として数えるのは上記8件のみ。全ブラウザーテスト、ビルド、型検査、lintは再実行していない。
- 前回の広いAppレビュー全体の再実施ではない。文法参照165項目の言語品質、回答正規化、別担当の教材修正は対象外。共有作業ツリーの最終統合検証は親担当が行う。
