# 文字の組立表示のレビュー

2026-11-12。対象は`HangulBuilder.tsx`、その単体・ブラウザーテスト、`App.tsx`への組込箇所、追加CSS、参照画面の言語指定と入力配列案内。`AGENTS.md`、教材仕様、`docs/UI_CRAFT.md`を基準に確認した。他担当の診断・評価機能は対象外。

## 指摘と受入結論

P0・P1の問題は検出しなかった。字母合成と課別範囲は受入可能。ただし、次のアクセシビリティ上のP2を修正してからUI全体を受け入れる。

- `src/features/learning/HangulBuilder.tsx`の`.hangul-parts`（役割のない`div`）と`.hangul-syllable`（`strong`）に付いた`aria-label`は、名前を付けられる意味的な役割を持たない。axeも`aria-prohibited-attr`を要手動確認として2要素報告した。支援技術では「初声・中声・終声」「組み立てた音節」というラベルが伝わらない可能性がある。可視テキストとして区分を示すか、適切な意味構造で関連付ける。`getByLabel`の成功だけでは支援技術での対応を証明できない。
- 同ファイルの字母選択肢は`lang="ko"`がなく、ページの日本語指定を継承する。教材仕様の韓国語部分の言語指定に合わせ、初声・中声の選択肢と、終声の「なし」以外に韓国語指定を付ける。日本語の欄名と「なし」は日本語のままにする。

## 確認した事実

- Unicodeの音節合成式と、初声19字・中声21字・終声のインデックス対応をコード上で確認。第1課は基本子音14字・基本母音10字、第2課は濃音・複合母音を含み、第3課から終声なしと代表7種を選択できる。課の切替では`key={l.day}`により前の課の選択が残らない。
- `AudioButton`には完成音節のみを渡し、単独字母のTTS再生は追加していない。未確認音声の表示がある。OSのIMEを利用する既存入力欄を置き換えていない。
- 見出しと選択欄を中心とした単純な構造で、装飾的なセカンダリラベルは追加していない。入力配列の案内は実機未確認の注意を維持している。
- `mise run test -- src/features/learning/HangulBuilder.test.ts`：1件成功。
- `mise run test:browser -- tests/browser/hangul-builder.spec.ts`：1件成功。第1〜3課の選択肢と合成結果を確認。
- agent-browserのChromiumで第3課を幅320pxで表示。文書の幅は320px、組立欄内の要素に画面右端を超えるものはなかった。選択欄のラベルはアクセシビリティツリーで取得できた。
- 組立欄に限定したaxe-core 4.12.1の結果は違反0件、要手動確認2ルール。上記ARIAのほか、装飾矢印の色対比が要手動確認だった。機械検査で違反0件という結果を、アクセシビリティの全面的な合格とは扱わない。

## 未確認

今回のレビューでは教材説明の独立した言語的照合、実音声、iPhone・WindowsのIME実機操作、スクリーンリーダーの読み上げは実施していない。Chromiumの幅320pxでの確認は実機確認を意味しない。参照画面のOS手順は差分と既存の調査記録を確認したもので、公式資料の再照合ではない。
